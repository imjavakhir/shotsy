# Shotsy — Photo Organizer

Native SwiftUI iPhone app (iOS 26.0+) that makes a big camera roll manageable: short swipe-sorting sessions,
Quick 20, a Screenshot Inbox with on-device text search, similar/duplicate/blurry/large-video cleanup, video
compression, Smart Collections, On This Day, People tagging, albums, and optional reminders.
Everything is analyzed on device. No server of our own, no cloud AI, no analytics SDK. Purchases run through RevenueCat.

## Build and run

Requirements: Xcode 26.x with the iOS 26 SDK (verified with Xcode 26.6 / iOS 26.5 SDK).

```bash
open Shotsy.xcodeproj
```

Choose the **Shotsy** scheme and an iPhone simulator, then Run. Until a RevenueCat API key is set in
`OwnerConfig`, the paywall shows "Purchases aren't set up in this build yet" and the app stays on the free tier.

Command line:

```bash
xcodebuild -project Shotsy.xcodeproj -scheme Shotsy -destination 'platform=iOS Simulator,name=iPhone 17 Pro Max' test
```

Swift Package dependencies (resolved automatically): `lottie-spm` 4.x (4.6.1) and RevenueCat `purchases-ios-spm` 5.x (5.91.0).

The project file is generated by `tools/generate_project.py`. Source folders are Xcode synchronized folders,
so new files are picked up automatically; only re-run the script to change targets or build settings.

## Architecture

```
Shotsy/App            entry, AppModel (service container, deep links), Router
Shotsy/Config         OwnerConfig, Policy
Shotsy/DesignSystem   brand tokens (light/dark), fonts, buttons, softAppBar(), shared components
Shotsy/Mascot         Canvas mascot + Lottie wrapper (brand kit assets)
Shotsy/Core           Photos, Persistence, Review, Analysis, People, Video, SmartCollections, Memories, Purchases, System
Shotsy/Features       Onboarding, Clean, Sort, Review, Screenshots, Memories, Library, People, Albums, Settings, Paywall
Shared/               deep links (reminder notifications)
ShotsyTests/          Swift Testing suites
brand/                original brand kit (SVG, Lottie, previews, generators)
```

- **Persistence:** SwiftData `SchemaV1` with a `SchemaMigrationPlan`. Two stores: *Main* (decisions, sessions,
  quota log, screenshot corrections/labels/pins, Smart Collections, compression jobs) and *Derived* (feature prints,
  sharpness, video sizes, OCR text, faces, people). The Derived folder is excluded from backup. Photos stays the
  source of truth: only asset identifiers are stored, never media.
- **Review engine:** `ReviewLedger` (pure) handles keep/mark/skip, undo, shared daily quota, and session pruning;
  `ReviewStore` persists after every decision.
- **Purchases:** RevenueCat is the only entitlement source (`PurchaseStore`). `EntitlementResolver` maps
  `CustomerInfo` to Free / Weekly / Lifetime (lifetime wins; an active weekly alongside it is shown with
  Manage Subscription). RevenueCat handles receipt validation, grace periods, refunds and expiry; the SDK caches
  customer info for offline use.
- **Concurrency:** UI on the main actor; analysis and face detection run in `@ModelActor` workers in batches, with
  cancellation between items and progress saved per batch.
- **Soft app bar:** `View.softAppBar()` applies `.scrollEdgeEffectStyle(.soft, for: .top)` to every main scroll
  container (grids, lists, forms), with native `NavigationStack` toolbars and no extra material layer.

## Features and how they work

- **Swipe sorting:** right = Keep, left = Mark for deletion (Shotsy's queue only). Buttons for Keep/Mark,
  plus Skip, Undo, Favorite, Add to album. Saved after every decision; resumes after termination.
- **Deletion:** review grid (deselect anything) → "Delete N items" → re-fetch and re-validate → PhotoKit's
  system confirmation. Success is shown only after Photos reports success; cancel/failure keeps the queue.
  After deletion: Recently Deleted for about 30 days; no fake restore, no storage promises.
- **Similar photos:** Vision feature prints (384 px local thumbnails) compared only with neighbors taken within
  10 minutes (≤40 each). Suggested keeper: favorite → resolution → sharpness → earliest, always overridable.
  At least one photo per group is always kept.
- **Verified duplicates:** near-identical, same-size candidates are verified by SHA-256 of **every** original
  resource (photo, Live Photo video, RAW/JPEG, adjustment data). Anything unreadable stays unverified.
  Verification is an explicit action; iCloud downloads are opt-in.
- **Blurry candidates:** variance of the Laplacian below a conservative threshold. Screenshots, videos and
  (by default) favorites are excluded. Labeled as suggestions.
- **Large videos:** size is measured from the local file only (no private KVC). iCloud-only videos show
  "Size unknown" and are listed separately, and the list says the order is incomplete.
- **Video compression:** AVAssetExportSession (HEVC 1080p, HEVC same size, H.264 720p) → temp file →
  playback/duration validation → measured size → preview → saved as a **new** asset with the original date and
  location. Spatial video is not offered. Loss of HDR (720p), cinematic focus, and slow-motion editability is
  explained. Larger or invalid outputs are discarded. Checks disk space. Job records prevent duplicate imports
  after interruption. Only after saving can the original be sent to the normal review.
- **Screenshot Inbox:** OCR with `RecognizeTextRequest` (accurate, on device). Categories come from conservative
  English keyword and layout rules (Receipts, Tickets, Recipes, Shopping, References, Other). Weak or mixed
  signals → Other. Corrections, labels and pins live in the main store and survive rescans. Links open only on tap.
  "Create Photos album" is a separate explicit action.
- **Quick 20:** frozen, deduplicated, unreviewed, not queued, capped by the remaining free allowance.
- **On This Day:** local-calendar day ranges; Feb 29 only on Feb 29; Feb 29 memories surface on Feb 28 in
  non-leap years; optional ±3/±7 day range; screenshots, hidden items and queued items excluded by default.
- **Smart Collections:** ALL/ANY rules with three-valued logic (yes/no/unknown). Unknown values (not indexed,
  size unknown, album gone) are reported, never counted as matches. Incompatible ALL rules are blocked.
  "Save as Photos album" makes a one-time snapshot and says so.
- **People:** see the dependency note below.
  Handles no access, no data, stale (>3 days), and complete. Links: Quick 20, continue session.
- **Reminders:** optional; permission is requested only when turned on. Weekday and time picker. Every change
  removes Shotsy's pending requests before scheduling, so nothing duplicates. Reconciled on time-zone changes.
  Text: "Ready for a quick photo sort?"

## People: automatic grouping is an open dependency

Vision (iOS 26.5 SDK, checked) detects faces and landmarks but has **no public face-identity embedding API**, and
Shotsy doesn't use Apple Photos' People data. Automatic grouping needs a face-embedding model whose **code and
weights** both allow commercial redistribution. None was bundled: common free models (FaceNet/ArcFace/InsightFace
variants) carry weights trained on datasets with non-commercial or unclear terms, and verifying and converting one
is engineering work this release didn't include.

What ships and works:
- On-device face detection (`DetectFaceRectanglesRequest` + capture quality), only after People is turned on.
- Manual tagging: name a person, tag faces, **Merge groups**, **Split group**, **Not this person** (remembered
  through rescans), **Add missing photo**, **Choose cover**, remove a person, **Delete People data**.
- A complete grouping pipeline, ready for a model: `FaceEmbedder` protocol, `CoreMLFaceEmbedder` adapter, crop
  normalization, and conservative `FaceGrouper` (centroid + majority check against chaining, respects rejections
  and manual tags, leaves singletons ungrouped). It's unit-tested with synthetic vectors only. This is **not** a
  measure of recognition quality.

To enable automatic grouping later, add a validated `ShotsyFaceEmbedder.mlmodel` (one image input, one MultiArray
output, preprocessing baked in) to the app target, tune `FaceGrouper`'s threshold on consented evaluation data, and
record the model source, revision/hash, and license below. Until then the UI says automatic grouping isn't available.

## Languages

English (base) + 12: Russian, Spanish, Portuguese (Brazil), French, German, Italian, Japanese, Korean, Chinese (Simplified),
Chinese (Traditional, Taiwan), Indonesian, Vietnamese. String Catalogs: `Shotsy/Resources/Localizable.xcstrings`
(app, with CLDR plural forms), `Shotsy/Resources/InfoPlist.xcstrings` (permission prompts).
Sources live in `tools/translations/`; rebuild with `python3 tools/build_localizations.py tools/translations`
(fails on any missing key or placeholder mismatch). Brand fonts cover Latin, Cyrillic and Vietnamese; CJK uses the system font.
New strings: add them to `tools/translations/all_keys.json` and each `tr_<lang>.json`, then rebuild.

- **Language:** iOS per-app language (Settings → Shotsy → Language); Shotsy's Settings links there. Unsupported device languages fall back to English.

## Privacy

- `Shotsy/Resources/PrivacyInfo.xcprivacy`: no tracking. Collected data: purchase history (app functionality, not linked) for RevenueCat. Confirm against RevenueCat's App Privacy guide. Required-reason APIs declared:
  UserDefaults (CA92.1), disk space (E174.1, checked before video export). Lottie ships its own manifest.
- Recognized text, face data and identifiers are never logged or sent anywhere. Derived data (OCR text, feature
  prints, faces, names) is stored in `Application Support/Shotsy/Derived`, excluded from backup.
- Settings: Clear analysis cache, Delete People data, and Reset review history never touch Photos.

**Performance, measured** (simulator on this Mac, Debug build): similarity grouping of 20,000 synthetic 768-d
feature prints takes **0.12 s**; building Quick 20 plus the pending queue over 50,000 decisions takes **7 ms**.
Not measured: a real 10k+ photo library on a device. There, Vision time per photo (≈ tens of ms) and thumbnail
loading dominate, so a first full scan of a large library will take minutes, in the background, resumable.

### Not verified (limitations of this environment)

- **iOS 27:** no SDK or runtime installed. Builds and behavior on iOS 27 are unverified. No iOS 27-only APIs are used.
- **Physical device:** no signing team configured, so no device install, no real iCloud-heavy or offline library.
- **Vision in the simulator:** feature-print generation fails in this simulator ("Could not create inference
  context"). The app handles it (items retry on the next scan), but similar-photo grouping was verified only through
  unit tests, not on real photos. Test on a device.
- **Purchases:** RevenueCat isn't configured (no API key), so no purchase, restore, expiry, or refund was exercised.
  Only the CustomerInfo → entitlement mapping is unit-tested. Test in sandbox once the key and products exist.
- **Reminders, VoiceOver, larger text, Reduce Motion/Transparency, small iPhones:**
  implemented, not manually verified.
- **Compression across formats, low disk, interrupted exports, failed imports:** logic unit-tested; real exports untested.
- **Large-library and cloud-heavy libraries:** not tested with real data.
- **Localization:** machine-assisted translations (by AI agents, validated for placeholders) — have a native speaker review before launch, especially legal/pricing lines.
